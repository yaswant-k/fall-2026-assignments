## PROMPT — HW2: Firewall (5 pts, due was Oct 2) — Reading: Du, Chapter 21
Setup: same VM; this lab's OWN setup files from the official SEED Labs Firewall page (normal folder in the VM). Containers (5): host-10.9.0.5 (Host A, outside), seed-router (10.9.0.11 / 192.168.60.11), host1-192.168.60.5, host2-192.168.60.6, host3-192.168.60.7. External network 10.9.0.0/24, internal 192.168.60.0/24; every packet between networks crosses the router. Keep three root shells open: Terminal 2 = router (all rules typed here), Terminal 3 = Host A, Terminal 4 = Host 1. Checkpoint: docker ps lists all five; root shells on router, Host A, Host 1.
Task 1A: record starting state (iptables -L -n: chains empty, policy ACCEPT). From Host A: ping 10.9.0.11 replies; telnet 10.9.0.11 (seed/dees, then exit) succeeds.
Task 1B (router, in this order): iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT; iptables -A OUTPUT -p icmp --icmp-type echo-reply -j ACCEPT; iptables -A INPUT -j DROP; iptables -A OUTPUT -j DROP; then iptables -L -n. Retest from Host A: ping still replies; telnet hangs (~10 s, then Ctrl+C — DROP is silent; REJECT would fail at once). Explain each rule's purpose and why ACCEPT exceptions come before DROP.
Cleanup before Task 2 (router): iptables -F; iptables -P OUTPUT ACCEPT; iptables -P INPUT ACCEPT.
Task 2A: on the router (ignore lo), run ip addr; complete the interface table (interface name; IP on router; external or internal?). Policy: (1) outside cannot ping internal; (2) outside CAN ping the router; (3) internal can ping outside; (4) all other cross-network traffic blocked. Explain why requirement 2 needs no FORWARD rule.
Task 2B (router; replace INT-IF/EXT-IF with your interface names, evidence tag with yours): iptables -A FORWARD -i INT-IF -o EXT-IF -p icmp --icmp-type echo-request -j ACCEPT; iptables -A FORWARD -i EXT-IF -o INT-IF -p icmp --icmp-type echo-reply -j ACCEPT; iptables -A FORWARD -j DROP; then iptables -L FORWARD -n -v. Tests: from Host A ping -c 3 192.168.60.5 → FAIL (100% loss); from Host A ping 10.9.0.11 → succeed; from Host 1 ping 10.9.0.5 → succeed. Trace the third test (which rule lets the request out, which lets the reply back in).
